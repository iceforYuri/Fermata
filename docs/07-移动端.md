# 07 · 移动端（Android）—— 同一版面，随身推进

> 状态：功能设计 · 第一部分（功能）、第二部分（同步）、第三部分（页面与动效）、第四部分（技术栈与 PoC）定稿（2026-10-18，逐条经用户确认）
> 定位一句话：手机独立完成安排、推进、计时、断点、完成、复盘；与桌面共同维护同一份版面、进程与历史。
> 边界：本文记录功能、同步、页面动效与技术栈决定；实施未开始，PoC 验收门见第 7 节。未有实施指令前不改动代码。

## 0. 范围与前提

- 服务范围（2026-10-18 定）：优先用户自己的一台 Windows 电脑 + 一台 Android 手机。
- 双端关系（2026-10-18 定）：共同维护同一份版面、进程与历史；同步协议见第 5 节。
- 设计宪法七条全部沿用：调度为内核、时间默认不计、颜色只属于色标、玻璃边界、无表单、推拉不弹窗、六原语薄接口。
- 用词沿用 CONTEXT.md：进程、挂起、稿库、断点、步骤栈、当前步骤、休止符、色标、已完栏、完成档案、休息态、回归、个人记录；「暂停」只指计时停止。

## 1. 进程与稿库（2026-10-18 定）

- 手机可完整编辑进程上下文：标题、色标、步骤栈、断点条、个人记录。
- 保留「等 AI」，双端语义一致。
- 稿库日期完整：无预定日 / 今天 / 明天 / 任意未来日期；过去未做的计划留原日期，不自动滚到今天。
- 排入与开始分开：排入只生成挂起进程；保留「直接开始」；已有运行进程时照常先确认断点；基本操作不依赖拖拽。
- 切换：先确认旧进程断点，预填已有内容、可直接确认，不强制新写；明确点「开始」才切换；点击进程主体 = 查看详情。
- 完成：明确点击完成（不用整行点击或普通滑动）；直接执行 + 5 秒撤销；之后经完成档案可重新打开；撤销 = 回挂起，不自动计时。
- 回归（扩展现行桌面合同，须双端统一设计，见第 6 节）：携带色标、当前断点、未完成步骤，排入生成新进程；已完成步骤、个人记录、过去用时留源进程，可回看；显式回归，不自动搬运昨日进程。

## 2. 计时与休止符（2026-10-18 定）

- 正常息屏、切后台继续计时；手机不做触摸空闲检测；打开应用、解锁不自动开始或恢复。
- 休止符双触发沿用：单进程时间片默认 45 分钟、连续工作默认 90 分钟，均可调；切进程不清零连续工作时间。
- 软 / 硬模式保留，默认软：
  - 软：到点仍计时，回到应用的自然间隙才进入休息态（例：45 分钟到点、70 分钟回来，约计 70 分钟）。
  - 硬：按触发时刻截止，不依赖通知是否被看到。
  - 休息态无自动恢复。
- 提醒：到点提醒一次；不循环响铃、不自动拉起应用；休息态不催促返回。
- 会话通知：显示当前进程、计时与运行 / 暂停 / 休息状态；支持暂停与显式继续（通知上的「继续」算显式恢复）；完成、切换须进应用。系统可行性待真机验证。
- 异常恢复：正常后台与普通系统回收 → 延续原会话，按软 / 硬模式计算；重启或无法确认持续性的异常 → 进入待确认：展示原进程与疑问区间，可选择是否计入、可修正结束时间；确认后仍需显式继续。
- 休息态可整理和查看：编辑计划、步骤、断点、个人记录不会恢复计时；明确继续 / 开始才开工。
- 跨午夜：正常运行跨午夜继续会话，用时按自然日拆分；时间环与连续工作计数不因午夜重置；今日仍能查看、暂停跨日会话。
- 历史计时不可任意编辑；仅两条例外：异常区间确认（上条）与零用时的「未计时完成」；完整补记修正后置。

## 3. 统计（2026-10-18 定）

- 完整复盘：年 / 月 / 日三个视角全保留；顶部小按钮展开视角选择，也支持统计模块内左右滑动切换；具体样式在页面适配阶段定。
- 日网格维持 06:00—24:00 不改（与桌面一致）。取舍留痕：跨午夜会话在 00:00—06:00 的用时照常按自然日计入数据与汇总，但日网格无格可画；将来凌晨场景成立时双端一起改，不由移动端单独扩展。

## 4. 设置与数据（2026-10-18 定）

- 设置五组：
  1. 计时：时间片长度、连续工作阈值、软 / 硬模式。
  2. 通知：开关状态 + 跳系统设置入口。
  3. 外观：浅色 / 深色 / 跟随系统。
  4. 数据：备份导出、恢复导入。
  5. 同步：连接 / 断开 WebDAV、最近同步状态、手动立即同步（见第 5 节）。
- 字号、密度是否可调：待页面适配阶段判断。
- 手动备份恢复独立于同步保留：以双端可读取的完整备份为目标（参照现行桌面快照 *.fermata.json，已覆盖进程、计划、步骤、分段、事件、设置、色板，见 docs/03-设置页.md 与 src-tauri/src/db/snapshot.rs）；导入展示日期与数据概况并说明覆盖，确认后先备份本机再恢复；版本不兼容说明原因、保留现有数据。

## 5. 同步（2026-10-18 定）

- 服务：坚果云 WebDAV（dav.jianguoyun.com/dav/，注册邮箱 + 第三方应用密码授权，应用密码在坚果云「安全选项」生成）。GitHub 方案记为技术备胎（国内手机访问不稳）。免费额度：上传 1GB/月、频率 600 次/30 分钟、单文件 500MB；服务端保留 3 个月文件历史版本，是本地备份之外的免费保险。
- 形态（首版）：整库单文件快照，复用 *.fermata.json 格式，gzip 压缩传输。实测当前库 0.41MB（2026-10），gzip 估算约 50KB；每天 50–100 次推送约 75–150MB/月，额度内从容。
- 范围：进程 / 计划 / 步骤 / 分段 / 事件 / 色板全量；设置中计时参数（时间片、连续工作阈值、软硬模式）同步，外观留本机，凭据留本机且不进快照。
- 触发：计时生命周期事件（开始 / 暂停 / 继续 / 完成 / 切换 / 休止符 / 接管）立即推；文本编辑防抖 30 秒推；启动时与回前台时拉（距上次拉取 >5 分钟才真拉）；不轮询。息屏后台推送受 Android 限制，并入真机验证清单。
- 运行锁：运行设备在开始 / 暂停 / 继续 / 停止 / 切换时写轻量标记（设备、进程、起始时间；WebDAV 小文件；带 TTL 过期）。另一端行内显示「在 X 设备运行中 · 始于 HH:MM」并锁定开始；想开始可显式接管——以对端最后标记时间为界结束对端会话、本端开始；标记过期后显示「可能仍在运行」，由用户显式决定。双端并行计时为 v2 候选，不进首版。
- 冲突检测：快照带 (rev 自增号, 设备 ID, 生成时间)；推前必读远端 rev（read-before-write），远端更新即冲突；用 rev 而非裸时间戳，免疫双端时钟漂移。
- 冲突处理（v1）：较新 rev 为有效版本；被覆盖端在覆盖前自动备份本机（带时间戳的 .fermata.json），UI 提示，可经手动恢复路径还原；绝不静默丢任何一端。离线 = 全功能正常使用，上线后走冲突流程。首次接入：远端空直接推 / 本地空直接拉 / 两端互不基于 → 按冲突处理（选方向 + 强制先备份）。
- 冲突递进：v1 整库 LWW + 备份；v1.5 实体级三方合并（以「上次同步版本」为基线；先例：KeePassXC 走 WebDAV 的数据库级实体合并）；v2 事件并集（合并 = 两端事件流并集按 ts 重放；同字段冲突落为后写赢，双端留痕可审计）。锁失效产生的重叠分段：双保留、统计照常、不自动删。
- 同步就绪 schema 约束（现在落，桌面侧补强）：所有实体（进程 / 计划 / 步骤 / 分段）与事件一律全局唯一 ID；一律维护 updated_at；删除一律留 tombstone（plans 已有软删除，步骤硬删除需补）；所有写操作必须进事件日志（现有 30+ 种 kind、41 个写入点，作同步源前需逐 kind 审计 payload 完备性）。
- 凭据：系统级安全存储（Windows 凭据管理器 / Android Keystore）；不写明文、不进快照、不同步；「断开连接」= 删除凭据、保留全部数据。
- 待确认状态（第 2 节异常恢复）为设备本地状态，不同步；确认后的分段修正照常同步。
- 实施范围：桌面新增 WebDAV 同步模块 + schema 补强；手机端绿地直接按本文建。目录布局等实现细节实施时定（建议 /fermata/snapshot.json.gz + /fermata/locks/<device>.json + /fermata/backups/）。

## 6. 页面与动效（2026-10-18 定）

- 导航：底部栏三枚（进程 / 统计 / 设置），沿用桌面 morph 语言——无容器底、无分隔线、图标 + 文字浮于版面、与背景自然融合；选中项弹簧展开为「图标 + 文字」。页面条带横滑：进程 ｜ 统计（内嵌 年｜月｜日，默认月；内部先切视角，划到年再右划回进程、划到日再左划进设置）｜ 设置。新页入场带一次低透明斜向柔光扫过（约 200ms，仅此一处，不循环不叠加）。
- 控件字形化：手机端控件一律用字形（×、✓、▸、⤒、+ 一族线性单笔画），不引图标库、不用 emoji；中文文字只留内容区（报头、统计标签、标题）。
- 稿库：左侧抽屉（与桌面同方位）；入口 = 进程页顶栏小按钮 + 屏幕左缘右滑手势（进程页是条带最左端，右滑无处可去，恰好自洽）。
- 详情卡：点击进程自下而上升起、覆盖大半屏。断点编辑区 = 当前在做进程的断点（预填自动断点，可改；对应桌面断点卡）；完整信息 = 被点进程（步骤栈 / 分段时长 / 个人记录，上滑浏览；对应桌面详情栏钉在被点这件）。编辑即时落盘、无保存按钮（宪法不动）。顶部两个图标按钮：⤒ 列为当前在做（= 桌面 Enter 完成切换）、× 关闭不切换（= 桌面 Esc）。点空白或下滑退出（overscroll 规则：内容未滚过时下拉即收缩；已滚下先回顶、再继续下拉收缩）。边界：无运行进程时 ⤒ 直接开始；点活跃进程自身时断点区即其自身、⤒ 隐去。
- 手势全集：点按 = 查看；长按 = 操作菜单；长按不松手拖动 = 菜单收起、进入拖拽排序（菜单与拖拽是同一手势流的两种出口）；稿库条目长按向右拖出抽屉 = 关抽屉 + 排入挂起队列（「直接开始」走长按菜单，排入 / 开始分离不变）；日网格点按整格出占用清单卡（替代 hover）；不引入左右滑动删除 / 完成（完成 = 明确点击 + 5 秒撤销，见第 1 节）。
- 视觉几何：日网格 18 列等比压缩全显（列约 19dp、圆约 14dp），不横滑，保住「一天一眼看完」；整格命中 + 底部清单卡；密度列入真机校验。时间环 64px 保留为活跃卡中心件，最后 5 分钟呼吸不动。字号阶梯 28/15/12.5/12 平移，跟随系统字号缩放。tokens 全部沿用桌面（底色 / 色标 / 卡片语言不动）。
- 横竖屏：竖屏优先；横屏不专门适配、不锁死（旋转不崩溃即可）。平板 / 折叠屏以后单独立项。
- 动效：页面横滑 1:1 跟手 + 松手弹簧归位（response 0.42s / zeta 0.86，沿用桌面 morph 参数，双端同一套物理）；详情卡 spring 升起、下滑收缩继承手势速度；稿库抽屉 spring 拉入；列表拖拽沿用 FLIP「先塌陷后开缝」插入预览语言；休息页 = 全屏玻璃遮盖自家内容（宪法允许位）。全部落成 design tokens，与桌面 tokens 同源。
- 参考边界：Gika 概念图（App Store id1628729687）只借结构与节奏，其深色高饱和不搬——月历日环、日网格点阵本就是从它演化而来的自家设计；截图因版权不入库。

## 7. 技术栈与 PoC（2026-10-18 定）

- 选型：Tauri Mobile（Tauri 2 Android 目标）+ 自写 Kotlin 前台服务插件。理由：单人维护、最大化复用（React 前端 / tokens / 动效 / 日网格 / Rust 数据层 rusqlite 在 Android 照常工作）；硬约束中必须原生的部分（前台服务、通知 action）任何方案都逃不掉；工具链（Android Studio + SDK/NDK + Rust 交叉编译 + 签名，项目目录 5–8GB）为一次性成本。
- 关键边界：双端合同 = 快照 JSON 格式 + 同步协议（第 5 节），不是共享代码；选型失败换方案时，本文设计与协议原样有效。
- 出局项留痕：PWA（Service Worker 息屏即停，不满足第 2 节息屏计时）；RN / Expo（无 DOM / CSS，UI 零复用不划算）；Flutter（全新栈零复用）；原生 Kotlin + Compose 留作退路（平台契合最高，但 UI 全重写 + 双份设计系统，单人长期成本最高）。
- 前台服务与通知：前台服务 + 常驻通知（暂停 / 继续按钮）由自写 Kotlin 插件承担；官方 notification 插件的 Android action 支持度列入 PoC 实测，不足则由同一插件自发通知。
- 安装：sideload APK，个人自用不上架商店，签名本机生成。
- PoC 验收门（任一失败先修复；确属硬阻断 → 按退路评估并记 deviation）：
  1. 真机构建安装成功；
  2. 前台服务保活：息屏 30 分钟计时不断、重开应用数据吻合（验第 2 节息屏计时）；
  3. 常驻通知「暂停 / 继续」按钮可操作（验第 2 节会话通知）；
  4. WebDAV 推 / 拉闭环（验第 5 节同步）。

## 8. 与桌面现行行为的差异（实施时须双端统一改，或记 deviation）

- 完成撤销：桌面现行为 3 秒，且撤销后原运行进程自动重开计时（src/store/actions.ts）；本文定为 5 秒、回挂起不自动计时。
- 回归：桌面现行只生成同名计划（仅标题，docs/02-统计页.md、src/pages/stats/StatsDetailOverlay.tsx）；本文扩展为携带色标 / 当前断点 / 未完成步骤。
- 跨午夜：桌面跨天重启将旧 running 自动挂起、同日重启可能自动重开计时（docs/deviation.md D63、src-tauri/src/db/ops.rs）；本文定为跨午夜延续 + 今日可查看、暂停。
- 同步就绪 schema：桌面需补全局 ID / updated_at / 步骤删除 tombstone，并审计事件日志完备性（见第 5 节）。
