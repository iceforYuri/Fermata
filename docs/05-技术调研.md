# 05 · 技术选型调研（合并校勘版，2026-09-18）

> 两路调研初判相反（代理证据链判 Electron / 用户侧调研稿判 Tauri），合并校勘后定案：**Tauri 2 主选（附 PoC 门槛），Electron 兜底**。决策与架构纪律见 ADR-0003；两稿原始结论的分歧原因与事实修正记录如下。

## 定案逻辑（为什么是 Tauri）

1. **反 Tauri 的最硬证据对本产品不适用**：Tauri 在 Windows 的 bug 群全部集中在**透明窗口路径**（#15512 backdrop-filter 在 transparent 窗口失效、#15490 每次 show() 白闪、#15947 透明+置顶黑块）。而本产品 Round 11 已定「玻璃语言边界」——液态玻璃只做**页内**效果（休息页/完成档案盖自家内容），对外浮层（休止符弹窗/切换浮层）是**实心暖卡** → 全程 opaque 窗口，一步不踏进 transparent，三雷全绕开；Win11 DWM 自动圆角（Win10 浮窗方角，可接受；开发者机为 Win11 build 26200）。
2. **剩余差距均为小工作量**：不抢焦点 = `focusable: false`（tao 源码级 WS_EX_NOACTIVATE，鼠标照常可点）；空闲检测 = `user-idle` crate / tauri-plugin-idlemonitor（~50 行 Rust）；热键/托盘/通知/自启/SQLite 全为官方插件。
3. **包体 3–10MB vs 90–100MB**（无争议的 Tauri 优势），与"轻量常驻工具"的产品气质一致。
4. **六原语薄接口**保证兜底迁移便宜（前端零改动）。

## 两稿事实修正（保留入档）

- 用户稿对 Electron 的两处过时描述：①"无 mica/acrylic API"不成立——`backgroundMaterial('acrylic'/'mica')` 存在（Win11 22H2+，electron#48031 已修）；②"透明窗口不可缩放"为旧限制，现行官方文档已无。均不影响裁决（窗口级亚克力对本产品只是加分项）。
- 代理稿的错误：把"液态玻璃浮窗"当成"透明玻璃浮窗"，忽略了自家玻璃边界规则——主反 Tauri 论据因此不成立，此为本轮改判的直接原因。
- **内存：两稿都不稳**。Elanis 2026-09 Windows 实测：Tauri（WebView2）进程 ≈317MB / 系统差值 ≈204MB，Electron ≈278MB / ≈104MB——Windows 上两者同量级（100–300MB），"Tauri 内存轻松达标"与"Electron 超标"均无依据；Tauri 的真实优势是包体与分发，不是常驻 RAM（macOS 上才相反）。
- 启动：同基准 Electron ≈206ms vs Tauri ≈711ms（冷启动，一天一次；浮层唤出 = 显示已建窗口，不受此影响）。
- 渲染一致性：Electron 固定版本 Chromium vs Tauri 跟随用户 WebView2 漂移——本产品 CSS 特性全为 baseline，风险低。

## PoC 门槛（M0 之前，1–2 天）

1. `focusable:false` + `show()` 的提醒弹窗：**不抢焦点 + 鼠标可点**
2. opaque 窗口内**页内 backdrop-filter** 满血（用休息页的玻璃原型试）
3. `global-shortcut` + `user-idle` 空闲回调跑通
4. 顺带确认 Win11 DWM 自动圆角

任一失败 → 触发 ADR-0003 兜底条款切 Electron，前端零改动。

## 排除项（两稿一致）

- **Flutter Desktop**：Windows 中文 IME bug 群活跃（flutter#191196 等）；无 CSS 排版体系；flutter_acrylic 停更、桌面集成社区包不稳
- **Wails**：v3 尚 beta（v3.0.0-beta.23）；v2 热键/空闲/多窗口需自造；官网被 Cloudflare 拦
- **WPF**：BlurEffect 为 CPU 软渲染，60fps 页内玻璃不可行
- **WinUI 3**：动能风险（转开源风波）、XAML 换代、AI 语料最少、仅 Windows
- **Avalonia**：页内玻璃仅实验性 ExperimentalAcrylicMaterial，无 backdrop-filter 等价物
- **Qt**：LGPL 动态链接义务或商业许可；AI 语料小
- **Compose MP / MAUI**：JVM + 无页内模糊 / Windows 上是 WinUI 套壳

## 前端选型（两稿一致）

React + TypeScript：AI 语料与社区积累最大，产出可靠度最高。配套纪律：视觉规则 design tokens 化（CSS 变量，与 01 视觉规格一一对应）；系统层六原语薄接口；设计文档（CONTEXT + 01–04）即编码模型的上下文。
