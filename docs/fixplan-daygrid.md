## F1 · 上滑加载跳底（事实性修复）

**现象**：日视角快速上滚触发 prepend 历史日后，视口跳到滚动区最底部（回到当天）。慢速步进滚动不出现。

**根因**：双重滚动补偿。代码在 prepend 后手动补 scrollTop（`DayGridView.tsx:79-87`，D38 设计）；Chromium 原生 CSS scroll anchoring 同时也补一次。快速滚轮连发时序下两者叠加成过度补偿，被钳制到最大滚动值 = 底部。数字严丝合缝：默认行为 40 次滚轮连发后 scrollTop 6809 = 底部钳制值 7445 − 剩余滚轮 636；注入 `overflow-anchor: none` 后同样输入原地不动（5265）。

**修复**：`.daygrid-scroll { overflow-anchor: none }`（baseline CSS，WebView2 支持无忧）。手动补偿机制保留。

**排除项**：导航栏（视角胶囊、吸顶小日期签）经排查与该 bug 无关。

**验收**：40 次快速滚轮连发后视口中心日 = 预期上滚位置，无跳底；慢速滚动行为不回归。

## F2 · 悬停浮窗口径

**现象**（三处）：
1. 悬停只显示"覆盖该格的进程段"整段起止——悬停 10:40 的圆点读到 09:20，第一眼"对不上"；浮窗从不显示时间格自身的 10 分钟窗口。
2. mock 与真实 exe 口径不一致：mock 取该进程**当天第一段**（真实使用中进程一天多段，下午的点会显示上午的起止）；Rust 侧逐格合并 min/max（较正确但同样不含格窗）。
3. 进行中的段：Rust 把结束时刻填成"当前时刻"，浮窗显示一个不断变大的结束时间。

**定稿口径**：浮窗 = 进程名 + **时间格内占用区间** + 时长；两行，字号字重照现状（`dg-tip-title` / `dg-tip-time num`）：

```
写方案章节
15:43–15:50 · 7m
```

- 区间钳制在时间格 10 分钟窗内：整格显示 `15:40–15:50`；起/止子格显示 `15:43–15:50`；进行中的当前格显示 `15:40–15:47`（端点 = 当下，纯数字自解释，不写"进行中"字样）。
- 起止越出 06–24 时窗的段（如 05:50 开段）钳制后自然收敛——显示的永远是格窗内的事实。
- 无断点行、无跨段信息（进程全貌归当天视图/详情面板管）。
- 冲突格两枚半圆各自悬停、各显其名与区间。

**术语**：10 分钟单位定名**「时间格」**，已写入 CONTEXT.md；该词不上 UI。

**改动**：`types.ts` GridCell 重构为每格最多两枚标记（含钳制起止、占用率、方向语义）；`mock.ts` 与 Rust `queries.rs` 的 `q_day_grid` 统一重写；`DayGridView.tsx` 浮窗渲染。

## F3 · 半圆/全圆规则（share 语义）

**现象**：代码里 share 算的是"格内所有进程总占用中主导者占比"（**支配率**），不是"这 10 分钟被占几成"（**占用率**）。单进程碰过的格 share 恒 1.0 → 永远全圆；半圆只在两进程冲突格出现（实测：历史某日 9 点全全圆；今天 17 全圆 + 3 半圆，3 个半圆均为冲突格）——所以"看不出来"。规格文档与 token 写的是 15/70，与本规则一并改为 20/80。

**定稿规则**（分母 = 时间格 10 分钟）：
- 占用 <20%：不画。
- 单一进程 20–80%：45° 斜半圆（段起 = 色右下、段止 = 色左上、中段默认右下）。
- 单一进程 ≥80% 且次者 <20%：全圆。
- 两进程都 ≥20%：同一枚 26px 圆按 45° 对角线分半——主导者色右下、次者色左上，各用各的色标色（复用现有 clip 机制，零新视觉语言）；此时起/止方向语义让位。
- 3 个以上进程 ≥20%：取占用前二。
- 连带约定：段尾不足 2 分钟（<20%）的尾巴格不画点——网格本就是 10 分钟分辨率。

**改动**：`tokens.css`（`--grid-min-share` 0.15→0.20、`--grid-half-threshold` 0.7→0.8）；mock/Rust 同步改 share 计算；`CellMark` 渲染每格至多两枚标记。

## F4 · 进场锚点

**现象**：进场把锚日 day-unit 的**顶**贴滚动区顶（`DayGridView.tsx:67-76`），下方留 264–333px 空白、大日期标悬半空；定位公式 `el.offsetTop − root.offsetTop` 存在 81px 系统偏差（offsetParent 混用）。实测 1.5s 采样 scrollTop 纹丝不动——无漂移，"锚点变动"感来自钻取动画 24px 升起。

**定稿**：进场时锚日**大日期标底缘 = 应用窗口底上方 40px**（token `--day-enter-gap: 40px`；实测滚动区底缘即窗口底）。统计表与日期标在单元内部的紧贴关系（gap 10px）不动；上一日尾巴自然铺在上方。定位公式改 getBoundingClientRect 相对量，消 81px 偏差。

**验收**：进场后连续采样 scrollTop 恒定；大日期标底缘距窗口底 40±2px；月视角双击任意历史日进场同样成立。

## F5 · 底部垫高（待确认）

**现象**：滚到最底，今天大日期标距容器底 312px = `padding-bottom: 240px`（v1.2"底部垫高让最后一天可读满"，服务于旧的贴顶阅读模型，已过时）+ 末单元 `margin-bottom: 72px`。

**方案（推荐）**：`padding-bottom: var(--day-enter-gap)`（40px）+ `.day-unit:last-child { margin-bottom: 0 }`。效果：**滚到世界的尽头 = 今天的进场位置**——同一条 40px 规则管两头，底部淡出遮罩（28px）恰好不碰日期标。
**备选**：垫高留 100px。
**状态**：待用户确认。

## F6 · 滚动条

**定稿**：日视角滚动条完全隐藏：`::-webkit-scrollbar { display: none }` + `scrollbar-width: none` 双保险（兼容旧版 WebView2）。导航路径 = 滚轮 + 月视角点日期直达 + 吸顶签回月；历史有上界（最早记录日）。范围仅日视角；月视角/设置页的滚动条后续另议。
