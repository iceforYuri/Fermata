# 断点双层模型与步骤栈

v1.1 设计修订（用户拍板）。v1 的断点是纯手写自由文本（切走时输入），步骤是尾部追加的清单；用户反馈断点维护负担重、与步骤脱节。定案：**步骤变栈**（新步骤置顶，旧步骤与已完成往下挤，勾选原位划线不沉底，可拖拽重排）；**断点双层**——自动断点 = 步骤栈顶未完成步骤标题（步骤新增/勾选/编辑/删除即跟随刷新）为默认；手动断点写入即钉住、不随步骤变更覆盖，清空手动回自动。

## Considered Options

- **纯手写断点（v1 原案）**：表达自由但维护负担全在用户，且与步骤清单信息重复。
- **全自动断点（取消手写）**：丢失"做到哪了"的语气与上下文细节（如"等评审意见"）。
- **双层（选定）**：默认零维护，需要时手写钉住。

## Consequences

- processes.breakpoint 语义改为"手动断点"（可空）；生效断点 = COALESCE(手动, 栈顶未完成步骤)，查询层派生（q_board）。
- CONTEXT.md 词汇更新：断点 / 自动断点 / 手动断点 / 步骤栈 / 当前步骤（已落）。
- 切换浮层留断点流程预填生效断点，Enter = 采纳；事件日志不变（breakpoint_set 只记手动，清空写 breakpoint_clear）。
- 无步骤且无手动断点时导语槽显淡字"未留断点"。
