# 断点与步骤统一为一个栈

v1.2 设计修订（用户拍板），修订 ADR-0004。双层模型（手动断点钉住 + 自动断点跟随）在概念上仍有两层要理解；v1.2 统一：**断点与步骤是同一个栈的两种条目**——步骤（可勾选）与断点条（▸ 便签、不可勾选）。写断点 = 压一条 note 到栈顶；导语槽 = 栈顶条目；`processes.breakpoint` 字段退役。

## Considered Options

- **双层（v1.1，ADR-0004）**：手动钉住 vs 自动跟随——规则要教，字段要维护。
- **纯步骤栈**：断点完全步骤化，丢失便签气质。
- **统一栈（选定）**：一种心智模型：栈顶即"做到哪了"；便签与步骤视觉同族可区分。

## Consequences

- `steps` 表 migration v3 加 `kind`（step|note，默认 step）；`breakpoint_set` 语义改为压 note 栈顶；`breakpoint_clear` 退役删除；新 `entry_delete`（删条目，写事件）。
- q_board 派生 `stack_top {title, kind}` 供导语；旧 processes.breakpoint 数据迁移为 note 条目。
- 切换留断点流程：写内容=压 note 到旧进程栈顶；空=不动；浮层预填=栈顶条目文本。
- 事件日志：breakpoint_set 不再产生（改 entry_add{kind:note}）；breakpoint_clear 不再产生；历史事件只读保留。
